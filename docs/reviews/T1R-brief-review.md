### M-1｜S1 目標日期與 Gate 日期（L48、L24、L90–L92）
**問題**：「盡快」不可驗證，G-01 基準期、D-1、D-2、D-3 都沒有實際期限。
**建議文字**（取代 L48）：
> 時程：專案結束展示 2027-02-〔維護者 決定：日〕。S1 目標上線日 2026-〔維護者 決定〕；G1 Gate 預定 2026-〔維護者 決定〕。S2 開始不晚於 〔維護者 決定〕，S3 不晚於 〔維護者 決定〕。G-01 基準量測期 = S1 上線日前 7 天。

D-1、D-2 的期限欄改為「G1（2026-〔日〕）」，D-3 改為「S3 開始前（〔日〕）」。

### M-2｜G-01、G-02、G-04 的判定方法（L22–L24、L26–L28、L34–L35）
**問題**：計數規則、記錄位置、驗收操作都沒寫，基準期和 S1 期間無法用同一把尺比較。
**建議文字**：
> **G-01 計數規則**：一次「轉貼」= 人把一段 AI 產出（或指令、交接文字）以複製貼上或手打的方式，送到另一個人或另一個 AI session。同一段內容送給多個對象，各算一次。記錄在 `docs/metrics/G-01-paste-log.md`（日期、時間、來源→目的、用途），基準期和 S1 期間用同一份規則。
> **G-02 驗收操作**：A 留一則交接給 B 後關閉 session；B 在 ≥10 分鐘後開新 session，只輸入「開始」。通過條件：B 的 AI 第一則回覆列出該交接的 ID 和摘要，以及專案現況，過程中不能有人轉貼。
> **G-04 驗收操作**：在 Discord 問「現在做到哪」，回覆要引用專案記憶中最近 N 筆紀錄的 ID 和時間；「@ 我」指 〔Discord @ 或 Agent Mail 收件人，維護者 決定〕。

### M-3｜G-03 的「即時」、問答／動手分類、auto mode 時限（L30–L32、L100）
**問題**：沒有延遲門檻，分類判斷者不明，限時沒有上限，測試者無法判斷結果。
**建議文字**：
> - 即時：B 的 agent 在 session 開啟時，收到 A 的訊息後 ≤〔暫定 60〕秒內顯示（暫定門檻，F-01 實測後重看）。
> - 分類：訊息由**發送方**標類型（`question`／`action`）；收件端只要內容涉及寫檔、執行指令、接任務、合併，就一律當作 `action`，以收件端判斷為準。
> - auto mode 時限：預設 〔維護者 決定〕 小時，上限 〔維護者 決定〕 小時，到期自動關閉並通知。

### M-5｜一段話範圍與任務真相來源（L40–L48、L54、L63、L35、L110）
