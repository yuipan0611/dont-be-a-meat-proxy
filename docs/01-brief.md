# 01 Brief — don't be a meat proxy

- 模板：專案流程 `02-通用模板/01-brief.md`；上游：`/project`（v1 種子簡報）

## 問題與證據

轉職班的新手工程師寫團隊專題時，每個人都靠自己的 AI 工作。維護者 所在組 7 人；全班 5 組，其他組人數待確認。人與人之間的協作只能**把自己 AI 的產出貼給對方，對方再貼給他的 AI**：

1. **人肉轉貼**：慢、會漏、會失真。
2. **組員不同時在線**：A 要交接時 B 不在，只能等，或在聊天軟體留一大段文字。
3. **AI 記憶斷裂**：每次開新 session 都要重講背景。
4. **工具不互通**：組員使用 Claude Code、Codex、Cursor、Antigravity，以及 VS Code（裝 Claude Code、Codex、Antigravity 擴充），各自的記憶與訊息機制互不相通。

現有基礎：Orca 原生 orchestration 已能讓 **維護者 一個人、同一台 Mac** 上的多個 agent 互相派工與回報（證據：`docs/orca-initialization.md`）。這套機制**不能跨人、跨電腦**。

來源：維護者 本人陳述（2026-11-16 訪談）。轉貼頻率與耗時尚未量測（見 G-01）。

## 本次交付

**S1**：維護者 一人在 Mac（Orca）、Windows（Claude Code）、手機（Discord）之間，讓 agent 能同步、非同步交換任務、交接、求助、決策，並能從手機查進度。分兩步交付：

- **MVP（2026-11-23）**：VPS 上的 AI 通訊＋驗證；Mac↔Windows 的 agent 能非同步交接、同步傳訊。
- **上線（2026-11-30）**：加上專案記憶、Discord bot、GitHub Issues，S1 完整；同時開放組員 `/connect`（S2 開始）。

S2、S3 是後續推廣階段，進入前各自另過 Gate；本 Brief 只定它們的成功條件。

## 目標與成功判準

### G-01｜人不再當 AI 之間的轉接站
- 計數規則：一次「轉貼」＝人把一段 AI 產出（或指令、交接文字），以複製貼上或手打的方式送到另一個人或另一個 AI session。同一段內容送給多個對象，各算一次。同時記錄大約耗時（分鐘）。
- 記錄位置：`docs/metrics/G-01-paste-log.md`（日期、時間、來源→目的、用途、耗時）。基準期與 S1 期間用同一份規則。
- 基準期：**2026-11-16～11-22**（MVP 前 7 天），由 維護者 記錄。
- 目標：S1 上線後兩週，維護者 本人的次數與耗時都減少 ≥70%（維護者 於 2026-11-16 設的暫定值，量到基準後重看）。

### G-02｜對方不在線也能非同步交接
- 驗收操作：A 留一則交接給 B 後關閉 session；B 在 ≥10 分鐘後開新 session，只輸入「開始」。
- 通過條件：B 的 AI 第一則回覆列出該交接的 ID、摘要與專案現況，過程中沒有人轉貼。

### G-03｜雙方都在線時能同步溝通
- 即時：B 的 agent session 開著時，A 的訊息在 ≤60 秒內被 B 的 agent 看到（暫定；F-01b 實測輪詢延遲約 0.2 秒）。
- 分類：發送方標類型 `question`／`action`；收件端只要內容涉及寫檔、執行指令、接任務、合併，一律當 `action`，以收件端判斷為準。`question` 可自動回答，`action` 要在 B 的畫面徵求 B 同意。
- 確認逾時：30 分鐘沒回應視為拒絕，並通知發送者。
- auto mode：由**收件人**對**指定對象**開啟，預設 1 小時、最長 4 小時，到期自動關閉；期間 `action` 可自動執行，每次都記錄並通知。

### G-04｜人能從手機掌握進度
- 驗收操作：在 Discord 問「現在做到哪」，回覆要引用專案記憶中最近的紀錄（ID 與時間）。
- 有人交接給我、或 Agent Mail 收件人是我時，Discord 通知我。可以從 Discord 建任務（先建成 GitHub Issue）。

### G-05｜新手 5 分鐘內接上
- 組員在 Discord 打 `/connect`，取得一段設定，貼進自己的 AI 工具後即可使用。只有 Claude Code、Antigravity 能做到一行指令；其他工具是一段設定（F-02）。
- 門檻：新手實測 ≤5 分鐘（暫定，S2 實測）。

### 系統構成（G1 已決定，細節由 SAD 定）

| 層 | 選擇 | 角色 |
|---|---|---|
| 任務看板 | GitHub Issues（官方 GitHub MCP） | 任務狀態的唯一真相 |
| AI 通訊 | mcp_agent_mail_rust，一組一個容器 | agent 身分、收件匣、同步／非同步傳訊；交接原文保存在這裡 |
| 專案記憶 | Hindsight，一組一個 bank，前面加 bank 代理 | 交接、決策的記憶；關閉 delete／clear |
| 驗證 | Caddy 反向代理 | 每人一個 token，可撤銷 |
| 人的入口 | Discord bot（以 js-llmcord 為底） | 通知、查進度、建任務、決策確認；身分＝Discord 帳號 |
| 專案助理 | 伺服器端 LLM，**唯讀**專案記憶 | 回答「現在做到哪」；Claude Haiku 5.5（D-4，F-07） |
| 本機指揮 | Orca（只在 維護者 的 Mac） | 組員**不需要**安裝 |
| 部署 | 維護者 既有的 Hostinger VPS（2 vCPU／8 GB RAM／100 GB） | 24 小時在線；不另付 VPS 費用 |
| 程式碼 | GitHub | Hub 只存 PR／commit 的連結 |

交換的內容有 4 種：**任務、交接、求助、決策**。

- 任務一律以 GitHub Issue 為準：從 Discord 或 agent 訊息建立的任務，先建成 Issue，訊息內只放 Issue 連結。
- 交接：session 結束時（或每完成一段）自動寫入；原文一律保存並可取回（Hindsight 萃取會漏資訊、會轉簡體，F-05）。
- 決策：草稿也寫入；轉為正式要確認。S1 由 維護者 確認；S2 起由提出者以外的任一組員確認，維護者 可否決。確認者、時間、草稿 ID 都寫入資料庫。
- 查進度的回覆預設只有提問者看得到，可選擇公開。

| ID | 這次不做 | 理由與重看時機 |
|---|---|---|
| NG-01 | 網頁版 ChatGPT／Claude／Gemini 接入 | 無法接 MCP；S3 後再評估 |
| NG-02 | 從遠端直接操作別人電腦上的 AI（非 auto mode 的情況） | 安全與除錯成本；auto mode 已涵蓋需要的情境 |
| NG-03 | Hub 存放原始碼 | 程式碼走 GitHub |
| NG-04 | LINE 作為主要入口 | bot 有訊息量限制；之後最多只用來收通知 |
| NG-05 | 完整的角色／權限系統 | 只做「收件人＋指定對象＋限時」的 auto mode |
| NG-06 | S1 階段就支援多組 | S3 再做隔離（架構上已一組一容器） |

## 限制、假設、風險與決策

- **限制**：個人預算（VPS 用既有的 Hostinger；LLM 用 Claude Haiku 5.5，每日上限 0.50 USD、Console 每月硬上限 5 USD，超過時助理回覆「今日額度已用完」並通知 維護者）；維護者 一人維運；工具限 MCP 相容的 CLI／IDE；時程只有兩週。
- **假設**：
  - A-1：Agent Mail Rust 版能放在 VPS、跨網路、多身分、可撤銷 → F-01b 已驗證 ✅。
  - A-2：各工具能用一段設定接上遠端 MCP → F-02 已驗證 ✅；VS Code 擴充是否沿用 CLI 的設定 → 待 F-08。
  - A-3：Claude Haiku 5.5 在上限內夠用（F-07 估每月約 0.91 USD ✅）；繁中品質待實作時實測，不成立時改用其他供應商（設定可替換）。
  - A-4：agent session 開著時能在 60 秒內收到新訊息（推播、hook 或輪詢）→ F-01b 輪詢可行；各工具的 hook 由 SDS 定。不成立時 G-03 降級為「下一次對話時收到」。 **結果（2026-11-17，維護者 同意）**：成立，判準為閒置 ≤60 秒、AI 忙時目前這一步結束後立即收到（F-09、H-04 實測）。
  - A-5：各工具能在 session 結束時觸發寫入交接；做不到就改為「每完成一段就寫入，結束前提醒」→ SDS 定。
- **風險**：
  - R-1 記憶污染：每筆紀錄要有類型、作者、來源 session；決策需確認。
  - R-2 auto mode 遭誤用：只有收件人能開、限定對象、限時、每次都留紀錄。
  - R-3 一人維運負擔：S1 兩週沒有資料遺失才擴大到 S2 全組。
  - R-4 金鑰外洩：每人一個 token，可在 Caddy／Discord 撤銷；禁止在 Hub 存放密碼或 API key。
  - R-5 專案 AI 使用規範：維護者 於 **11-30（S2 開始）前**向指導者確認；不允許時只保留 S1。
  - R-6 Agent Mail 授權附加條款（限制 OpenAI／Anthropic）：維護者 決定接受風險（G1）。
  - R-7 問答自動回答造成外洩：自動回答只能引用專案記憶和 repo 內容。
  - R-8 他人資料保管：S2 起 VPS 存組員的 Discord ID 和訊息；`/connect` 時告知保存與刪除方式。
  - R-9 兩週時程過緊：MVP 只做通訊＋驗證；記憶與 Discord 放第二週。
- **待決**：
  - D-3：S3 是否改由各組自備 LLM key → S2 Gate 由 維護者 決定。
  - ~~D-4~~：已決定，Claude Haiku 5.5（方案 B）。
